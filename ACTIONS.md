<a id="цель"></a>

## Куда отправлять: цель действия

Большинство действий принимают один из способов указать чат:

| Способ | Поля | Когда удобно |
|--------|------|----------------|
| Сущность чата | **`entity_id`** (или «Цель» в UI) | Выбрать готовый чат MaxNotify (`notify.…`). Можно **несколько** сущностей за один вызов (кроме `delete_last_outgoing_message` и `send_text_to_all`). |
| Запись + ID чата | **`config_entry_id`** + **`recipient_id`** | Ответ **в тот же диалог**, откуда пришло событие `max_notify_received`: оба значения берут из `trigger.event.data`. Сущность `notify` для этого не нужна. |
| Только запись | **`config_entry_id`** | Если у записи **один** чат — сообщение уйдёт в него. Если чатов несколько — без `entity_id` / `recipient_id` выбор неоднозначен: укажите цель явно. |

**`recipient_id`:**

- **больше 0** — личный чат (`user_id`);
- **меньше 0** — группа или канал (`chat_id`).

Тот же смысл, что в событии `max_notify_received`. Если указать `recipient_id` вместе с `entity_id`, остаются только сущности с этим получателем.

Поля **`config_entry_id`** и **`recipient_id`** у отправки обычно в блоке **«Дополнительные настройки»** (свёрнут по умолчанию).

<a id="общие"></a>

## Общие параметры отправки

Эти поля есть у текстовой и медиа-отправки (где применимо). У `edit_message` — свои правила для кнопок (см. [ниже](#edit-message)).

<a id="format"></a>

### Формат текста (`format`)

| Значение | Смысл |
|----------|--------|
| *(не указан)* | Формат из **настроек записи** MaxNotify |
| `text` | Обычный текст без разметки |
| `markdown` | Markdown |
| `html` | HTML |

Влияет на:

- текст **`message`** / **`title`** при отправке;
- **подпись** (`caption`) у фото, документа, видео;
- новый текст при **`edit_message`**.

Для **notify.a161.ru** доступные форматы могут ограничиваться ответом сервера о возможностях токена.

<a id="notify"></a>

### Уведомление (`notify`)

| Значение | Смысл |
|----------|--------|
| `true` (по умолчанию) | Обычное сообщение с уведомлением получателей |
| `false` | Попросить Max отправить **без** push-уведомления («тихо») |

Параметр есть у: `send_message`, `send_text_to_all`, `send_photo`, `send_document`, `send_video`.

Он попадает в тело запроса к API, но **клиенты Max ведут себя по-разному**:

- в **личном** чате с ботом уведомление часто показывают **все** клиенты даже при `notify: false`;
- в **группе / канале** при `notify: false` мобильный клиент обычно молчит, веб и десктоп могут всё равно показать push.

Сообщение в ленту при этом доставляется. Подробнее — [README → Поведение уведомлений](README.md#поведение-уведомлений-и-каналы).

<a id="клавиатура"></a>

### Клавиатура и кнопки

| Параметр | По умолчанию | За что отвечает |
|----------|--------------|-----------------|
| **`send_keyboard`** | `true` | Учитывать ли **постоянную** inline-клавиатуру из настроек записи |
| **`buttons`** | *(нет)* | **Свои** кнопки **только для этого вызова** |

Правила (одинаковы для отправки текста и медиа):

| `send_keyboard` | Поле `buttons` | Что уйдёт в сообщение |
|-----------------|----------------|------------------------|
| `true` | не передано | Клавиатура из **настроек записи** (если задана) |
| `true` | передано, но после разбора **пусто** | Клавиатура из настроек записи |
| `true` | передано и **непустое** | **Только** эти кнопки (заменяют сохранённую клавиатуру, **не** склеиваются с ней) |
| `false` | непустое | Только кнопки из вызова |
| `false` | нет / пусто | Без клавиатуры |

Типы кнопок: **callback**, **message**, **link**. Для **link** URL только с `http://` или `https://`.

**Исключение:** у **`send_document`** inline-клавиатура **запрещена** (ограничение Max API: документ — единственное вложение). По умолчанию `send_keyboard: false`; если включить клавиатуру или передать непустые `buttons`, вызов завершится ошибкой.

Форматы поля `buttons` (все допустимы):

```yaml
# Один ряд — словарь «подпись → payload»
buttons:
  "Да": "yes"
  "Нет": "no"

# Один ряд — список объектов
buttons:
  - text: "Да"
    payload: "yes"
  - text: "Сайт"
    type: link
    url: "https://example.com"

# Несколько рядов
buttons:
  - - text: "Ряд 1 / A"
      payload: "r1a"
    - text: "Ряд 1 / B"
      payload: "r1b"
  - - text: "Ряд 2 / A"
      payload: "r2a"
```

Ещё варианты и сценарии — в [AUTOMATIONS.md → Форматы buttons](AUTOMATIONS.md#formats-buttons). Для кнопок типа callback в автоматизации фильтруйте событие по **`callback_data`**.

## max_notify.send_text_to_all

Экспериментальная рассылка: тот же текст **во все добавленные чаты всех записей** MaxNotify. Записи без ни одного чата пропускаются. **`entity_id` / `config_entry_id` / `recipient_id` нет** — цель задавать не нужно.

| Параметр | Обязателен | Где в UI | Описание |
|----------|------------|----------|----------|

| **`notify`** | нет (`true`) | доп. | См. [notify](#notify). |
| **`send_keyboard`** | нет (`true`) | доп. | Клавиатура из **настроек каждой** записи отдельно. |
| **`buttons`** | нет | доп. | Одинаковые свои кнопки для всех получателей этого вызова. |

## max_notify.send_photo

Отправить одно или несколько **фото** одним сообщением.

| Параметр | Обязателен | Где в UI | Описание |
|----------|------------|----------|----------|
| **`file`** | да*, если нет `files` | основное | Один локальный путь (`/config/…`, `/media/…`) **или** URL `http`/`https`. Ссылка сначала скачивается во временный файл HA, затем уходит в Max. |
| **`files`** | да*, если нет `file` | основное | Список путей/URL — несколько вложений **в одном** сообщении (вместо `file`). |
| **`caption`** | нет | основное | Подпись к фото (с учётом `format`). |
| **`entity_id`** | см. [цель](#цель) | Цель | Одна или несколько сущностей. |
| **`format`** | нет | доп. | Формат **подписи**. |
| **`notify`** | нет (`true`) | доп. | См. [notify](#notify). |
| **`send_keyboard`**, **`buttons`** | нет | доп. | См. [клавиатура](#клавиатура). |
| **`config_entry_id`**, **`recipient_id`** | см. [цель](#цель) | доп. | Как у `send_message`. |
| **`count_requests`** | нет | доп. | См. [медиа](#медиа-url). |
| **`disable_ssl`**, **`url_auth_*`** | нет | доп. | См. [медиа](#медиа-url). |

\* Нужен хотя бы один источник: `file` или `files`.

На стороне Max действует общий лимит вложений на сообщение (до **12**, включая inline-клавиатуру как вложение). У **notify.a161.ru** дополнительно проверяется размер файла (см. [README](README.md#сервис-notifya161ru)).

Отправить одно или несколько **видео** (типичные форматы: **mp4**, **mov**, **webm**, **mkv**).

<a id="медиа-url"></a>

## Параметры медиа по ссылке и повторы

Общие для **`send_photo`**, **`send_document`**, **`send_video`** (блок «Дополнительные настройки»).

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| **`count_requests`** | авто (несколько попыток с паузами) | Сколько раз повторить POST сообщения, пока Max отвечает, что вложение ещё обрабатывается (`attachment.not.ready`). Диапазон в UI: **1–60**. Для больших файлов и видео увеличивайте. |
| **`disable_ssl`** | `false` | Отключить проверку SSL **для этой** операции (скачивание URL и/или запросы к API в рамках отправки). Только если понимаете риск (самоподписанный / «битый» сертификат у источника). |
| **`url_auth_type`** | *(нет)* | Авторизация при **скачивании** файла по URL: `basic`, `digest` или `bearer`. Нужна, если ссылка закрыта учётными данными. |
| **`url_auth_login`** | | Логин для basic / digest. |
| **`url_auth_password`** | | Пароль для basic / digest. |
| **`url_auth_token`** | | Токен для bearer. |

Поведение ссылок:

1. Файл по `http`/`https` **один раз** скачивается во временную папку Home Assistant.
2. В Max уходит уже локальный файл.
3. При рассылке в несколько чатов повторного скачивания той же ссылки нет.
4. После отправки временный файл удаляется.

Скачивание произвольных URL **не входит** в общий лимит исходящих запросов к API Max (см. [ограничения](#ограничения)).

<a id="delete-message"></a>

## max_notify.delete_message

Удалить сообщения в чате. Ошибки валидации показываются в HA **с переводом** (ru / en и др.).

У бота в чате должны быть права **читать** и **удалять** сообщения. В группах и каналах обычно нужна роль **администратора** с соответствующими разрешениями.

На стороне платформы Max сообщения **старше 24 часов** удалить нельзя (ограничение API, не Home Assistant).

### Параметры

| Параметр | Обязателен | Описание |
|----------|------------|----------|
| **`message_id`** | один из режимов | Один ID или несколько через запятую в одном поле. |
| **`message_ids`** | один из режимов | Список ID (через запятую или массив в YAML). |
| **`date`** | один из режимов | Один **календарный день** в **локальной** зоне HA (00:00:00–23:59:59). Только дата без времени или Unix timestamp (берётся день момента). |
| **`from`** + **`to`** | один из режимов | Интервал поиска: нужны **оба** поля. |
| **`entity_id`** | см. цель | Сущность notify (можно вместо `config_entry_id`). |
| **`config_entry_id`** | см. цель | Запись MaxNotify (обязательна при нескольких записях, если нет сущности). |
| **`recipient_id`** | нет | При удалении по **дате / интервалу** — ограничить поиск этим чатом. |

Одной только сущности notify **недостаточно**: нужно указать способ поиска (`message_id` / `message_ids` / `date` / `from`+`to`).

### Приоритет полей (сверху вниз)

Если задано несколько способов, используется **только верхний**, остальные игнорируются:

1. **`message_id`**
2. **`message_ids`**
3. **`date`**
4. Пара **`from`** и **`to`**

### Период и дата

- Интервал: заполните **оба** конца **или** ни одного (если удаляете по ID / дате). Одна граница без второй — ошибка.
- Поле **«Дата»**: время в строке **запрещено** (будет ошибка). Unix timestamp допустим — берётся календарный день.
- Форматы даты/времени для `from` / `to` и даты без времени:  
  `2026-10-23`, `2026.10.23`, `2026/10/23`, `23.10.2026`, `23-10-2026`, `23/10/2026`;  
  с временем — через пробел или `T`, время с `:` или `-` (`2026-10-23 00:00:00`, `23.10.2026 00-00-00`). Допускается Unix timestamp.

### Официальный API и notify.a161.ru

| Возможность | Официальный API | notify.a161.ru |
|-------------|-----------------|----------------|
| Удаление по `message_id` / `message_ids` | Да | Да (если сервер разрешил удаление) |
| Удаление по **дате** или **интервалу** (поиск, затем DELETE **по одному** `message_id`) | Да | **Нет** |
| Действие **`delete_last_outgoing_message`** | Да (группы) | **Нет** |

### Ответ действия

При вызове из UI в ответе может быть объект **`deleted`** — сколько сообщений успешно удалено.

### Пример запроса вручную (notify.a161.ru, только по ID)

```text
DELETE https://notify.a161.ru/messages?message_id=mid.<ваш_id>
Authorization: <токен из настроек записи>
```

YAML-примеры — в [AUTOMATIONS.md](AUTOMATIONS.md#autom-delete-message).

## max_notify.delete_last_outgoing_message

Найти и удалить последнее **исходящее** сообщение бота в **групповом** чате.

| | |
|--|--|
| **Провайдер** | Только **официальный API Max**. У notify.a161.ru действие недоступно. |
| **Чаты** | Только группы / каналы (`recipient_id` **&lt; 0**). В личных чатах официальный API не отдаёт историю по получателю — используйте явный `message_id` в `delete_message`. |

| Параметр | Обязателен | Описание |
|----------|------------|----------|
| **`entity_id`** | **да** | Ровно **одна** сущность notify MaxNotify (чат). |
| **`config_entry_id`** | нет | Запись интеграции (если нужна однозначность при нескольких записях). |
| **`scan_count`** | нет (**20**) | Сколько последних сообщений в чате просмотреть при поиске исходящего бота. Диапазон **1–100**. |

<a id="edit-message"></a>

## max_notify.edit_message

Изменить уже отправленное сообщение: текст и/или кнопки.

На стороне Max сообщения **старше 24 часов** править нельзя.

| Параметр | Обязателен | Описание |
|----------|------------|----------|
| **`message_id`** | **да** | ID сообщения (часто из `trigger.event.data.message_id` или сенсора после отправки). |
| **`text`** | нет | Новый текст. Если не указать — текст не меняется. |
| **`format`** | нет | Формат нового текста: `text` / `markdown` / `html`. |
| **`send_keyboard`** | нет (`true`) | Как сочетать кнопки с клавиатурой из настроек (см. ниже). |
| **`buttons`** | нет | Новые inline-кнопки. |
| **`remove_buttons`** | нет (`false`) | `true` — **снять все** inline-кнопки с сообщения. |
| **`entity_id`** | см. цель | Сущность notify. |
| **`config_entry_id`**, **`recipient_id`** | см. цель | Запись и чат, если сущность не выбрана. |

Клавиатура при правке (поле **`buttons` не передано** — кнопки сообщения **не меняются**, меняется только текст, если задан):

| `remove_buttons` | `send_keyboard` | Поле `buttons` | Результат |
|------------------|-----------------|----------------|-----------|
| `true` | любое | любое | Все inline-кнопки **снимаются** |
| `false` | `true` | передано и **пусто** | Ставится клавиатура из **настроек записи** |
| `false` | `true` | передано и **непустое** | Клавиатура сообщения **заменяется** на эти кнопки |
| `false` | `false` | передано и непустое | Ставятся только кнопки из вызова |
| `false` | `false` | передано и пусто | Кнопок не будет (пустая клавиатура из вызова) |

## Ограничения платформы и провайдеров

- **Исходящие HTTP к API** Max / notify.a161.ru: на экземпляр Home Assistant — **не более ~30 запросов в секунду** суммарно (отправка, удаление, правка, опрос `/updates`, подписки WebHook и т.д.). Скачивание медиа по произвольным URL в это число **не входит**.
- У **notify.a161.ru** между исходящими запросами к **одной** записи выдерживается пауза порядка **1 секунды**; лимиты размера и доступные операции зависят от ответа сервера о возможностях токена.
- Возможности вроде удаления по периоду и «последнего исходящего» завязаны на флаги провайдера; при недоступной операции HA покажет переведённую ошибку, запрос к API не уйдёт.
- **Документ + inline-клавиатура:** платформа Max не допускает клавиатуру вместе с вложением `file` — интеграция отклоняет такой вызов до запроса к API.

Сводка отличий notify.a161.ru — в [README](README.md#сервис-notifya161ru).
